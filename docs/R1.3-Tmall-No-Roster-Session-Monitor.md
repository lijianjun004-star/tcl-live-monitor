# R1.3 淘宝／天猫单店｜无需排班的直播场次观测

## 范围和用户决策（2026-11-08）
- 第一家且唯一目标：**TCL集团官方旗舰店**，淘宝用户ID \`2050532947\`；历史 roomNum \`130742\`。
- **不导入排班表**，不要求用户一直开手机/电脑，不查询销售额/评论等无关数据。
- 只关注：是否 LIVE、首次检测开播时间、首次检测下播时间、估算的直播时长，以及真实性/未知原因。
- 直播中每15分钟观察；确认下播后**本场结束**，只在每60分钟的低频时点寻找下一次开播。无排班又完全不做发现请求，不可能自动知道下一场何时开始。
- 若需要不漏掉短于1小时的排班外开播，只能把低频发现周期缩短，或取得平台推送事件；当前不假设存在后者。

## 真实性红线
- 从原始平台状态读取且历史身份门禁通过才能 LIVE/OFFLINE；错误、异常、RGV587、缺字段、账号或直播间不匹配统一 UNKNOWN。
- 一次 OFFLINE 只标记 PENDING_END；必须第二次相邻有效 OFFLINE（最大间隔25分钟）才结束本场，否则保持开放。
- 最早能说的是“首次观测到LIVE”；无法还原实际开播秒。
- 下播时间是“首次观测到OFFLINE”；实际下播发生在最后一次 LIVE 与第一次 OFFLINE 之间（仅在两次样本可信时成立）。
- \`estimatedContinuousLiveMinutes\` 是无UNKNOWN插入、相邻两次LIVE时间差的**估算观察跨度**，并非证明全程连续播出的准确时长，严禁等同于满播时长。
- 观察超过30分钟没更新，当前状态 UNKNOWN，不沿用昨天的 LIVE/ OFFLINE。
- 不进行扣分、正式统计；关闭任何自动考核。
- 当前有来自GitHub Actions的**历史**真实采样，但本轮没有新淘宝数据源。此前浏览器安全策略阻断，不通过其它路径绕过；有新获准数据源后才启动真实巡检。

## 本次实际代码
- \`probes/lib/r13-tmall-interval-monitor.mjs\`：会话状态机（IDLE_DISCOVERY、LIVE_FOLLOW_UP；场次 OPEN/PENDING_END/CLOSED）、去重、身份门禁、限流降级、时间戳过期、场次估算、不按排班。
- \`probes/r13-single-store-report.mjs\`：从离线JSON读取观测样本（无联网行为），输出手机可查看的静态 \`index.html\`、\`state.json\`、\`report.md\`。
- \`tests/r13-tmall-interval-monitor.test.mjs\`：32个真实历史回放／边界和合成故障测试。明确区分真实历史样本和人工构造测试记录。
- \`.github/workflows/r13-tmall-session-gates.yml\`：只测试和制作报告制品，不包含 \`schedule:\` 和平台访问动作。
