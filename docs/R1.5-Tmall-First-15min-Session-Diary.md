## 用户确认
- **只做第一家** TCL集团官方旗舰店：平台账号 `2050532947`、历史房间 `130742`。
- 不导入排班表、不持续打开直播页面、不采集实时弹幕。
- 接受间隔观察的**近似**上播／下播时间，优先记录每场直播：是否开播、首次发现开播、首次发现下播、确认下播、估算的直播跨度及每次查询状态。

## 这次真正实现的文件
- `probes/lib/r15-session-diary.mjs`：**只用真实、已记录的观察证据**生成状态时间点、按天分组、每场直播开播／下播窗口、时间误差说明和可追溯拒绝原因；禁止跨账号混用、冲突去重、过期快照判UNKNOWN、未知时长不补算。
- `probes/r15-build-diary.mjs`：将历史 Actions 原始观测样本或 R1.4 可恢复 JSON 转成手机可阅读 `index.html`、`diary.json`、`timeline.csv`、`sessions.csv`。CSV 防公式注入；界面无需额外付费依赖。
- `tests/r15-session-diary.test.mjs`：30条专项回归，覆盖真实 GitHub Actions 历史数据、时间窗口、未开播／待确认、中文 CSV 和安全降级。
- `.github/workflows/r15-tmall-diary-offline.yml`：GitHub 上**自动构建和测试报告制品**，不会联系淘宝。下载 Actions artifact 后手机打开 HTML 即可查看历史示例。

## 证据意义：非常重要
- `firstLiveDetectedAt` 是第一次看到 LIVE 的采样时间。若此前有可信 OFFLINE，则实际上播时间**可能在上一 OFFLINE 与第一次 LIVE 之间**；否则只能说“不晚于第一次发现 LIVE”。
- `firstOfflineDetectedAt` 是第一次看到 OFFLINE；以两次可信 OFFLINE 作为确认下播条件。实际下播时间属于最后一次已知 LIVE 与第一次 OFFLINE 之间，而不是首次发现下播的精确分钟。
- `estimatedObservedLiveMinutes` 仅表示**相邻、成功、间隔合理的LIVE样本之间的时间跨度估计**，不能当作平台原始开播时长；未观测时间段不补记。
- `UNKNOWN` 包括登录要求、限流 RGV587、脚本错误、身份冲突和样本缺失；绝不能当成 OFFLINE。
- 数据显示均以**北京时间**呈现；源 JSON 的时间戳仍保留 ISO8601 UTC，便于审计。

## 当前尚未完成、不得冒充
- 当前平台直播接口：**没有验收通过的获准稳定数据源**。历史 Actions 曾出现 LIVE 与 RGV587 限流，不能承诺每15分钟都成功。
- 本 PR 内没有真正启动淘宝采集，没有 cron，没有持续数据写入或公开 Pages 站点部署，不修改 `main`，不运行正式时长考核。
- Actions `schedule` 仅在默认分支触发，且可能延迟或漏触发；必须先通过真实数据源和跨多次 workflow 的长期存储验收才能考虑启用。
- R1.4 的状态恢复只演示了同一 Actions workflow 的**跨作业**交接；不是持久数据库。长时间存储要另外选择免费数据存储（并验证权限、并发和保留期）。
- 代码和离线报告“可用”，**真实自动巡检暂不可用**，在平台数据源受限时保持 `UNKNOWN`。
