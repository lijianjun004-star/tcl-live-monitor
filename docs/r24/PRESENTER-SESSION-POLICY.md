# TCL R2.4｜真人下播后开启数字人：场次分段规则

日期：2026-11-10。此版本仅添加**纯离线状态机**与回归测试，未接入平台视频、回放，也不修改任何正式巡检数据。

## 项目业务规则（来自 TCL 运营反馈）
- 数字人只在真人直播结束后开启；不能把真人正在直播时出现的数字人直接认定为一次合法切换。
- 同一店铺是否正在 LIVE 与“当前是真人还是数字人”是**两套不同维度**；店铺 LIVE 不能自动等于真人 LIVE。
- 淘宝／天猫、京东若无足够画面／回放证据，则主播类型必须为 UNKNOWN。
- TCL 抖音当前按真人业务管理；若出现数字人证据，生成**需要人工核实的业务规则冲突**，不把“平台技术上绝不可能”当作结论。
- 长时间同一张脸**不足以**证明数字人；换人只能作为真人出镜的有力线索，不能证明每个时段都是实时真人直播。

## 事件模型
输入包含平台、稳定店铺标识、唯一观察 ID、UTC 时间、事件类型及审核后的证据标记。
- HUMAN_PRESENT：经过画面/回放/运营审核的真人出镜观察。
- HUMAN_STOP_OBSERVED：观察到真人结束该时段（不是平台精确下播时间）。
- DIGITAL_PRESENT：经审核确认的数字人出镜观察。
- DIGITAL_STOP_OBSERVED：观察到数字人结束该时段。
- SIGNAL_UNKNOWN：无证据/来源异常/丢失。**不推断 STOP 或 OFFLINE。**

转移约束：HUMAN_PRESENT → HUMAN_STOP_OBSERVED → DIGITAL_PRESENT 才能把交接标记为“已观察到先真人结束再数字人出现”。如果数字人直接出现但先前真人结束不可核实，记录已审核的数字人画面，同时标记前序交接尚未确认。真人活跃时出现数字人观察，视为冲突待核实而不是两者重叠。

## 字段与安全
- 记录段首首次发现时间、段末结束被观察时间、上次观察时间；**不等同实际开播/下播时刻**。
- 不计算真人/数字人准确时长、完成率或连续性；相关字段保持 null 或 false。
- 不存视频帧、主播姓名、Cookie、账号密码、平台接口数据。输入证据枚举只声明经过审核，不会自行验证视频真假。
- 按平台 + 店铺隔离；同一 ID 重试幂等；乱序及 ID 冲突拒绝；UNKNOWN 不触发虚构交接。
- 该分类模块尚未连接 R2.3 京东采样源，也不代表真人/数字人自动识别已完成。

## 运行离线复验


独立工作流：`.github/workflows/r24-presenter-policy.yml`。无生产 schedule、无实际网络平台访问、无自动合并或 Pages 部署。

## 下一道真实验收
先取得**经过授权正常访问的真实回放/画面与时间戳**，执行人工标注 A/B（真人段 / 数字人段）与边界复查，再评估可靠的视觉识别算法及假阳性率。只有经过验证的上下播来源和排班匹配后，才能正式计算真人上播时长与满播率。
