# 巡检遇到滑块或画线验证时，用手机完成

## 做什么

天猫房间在 V2 巡检中碰到人机验证（滑块、按轨迹画线等，代码 `CAPTCHA_X5SEC`）时：

1. 这个房间暂停，页面重新加载一次，让验证页完整显示。
2. Bark 推送"巡检需要人工验证"到手机。推送里的链接带一次性口令，5 分钟内有效。
3. 点开后能看到云端浏览器的实时画面。按画面提示用手指拖动滑块或画线。手指的按下、移动、松开会按顺序转成云端页面里的触摸动作。
4. 页面拿到直播数据后，这个房间按真实结果记录（在播或未播），同组后面的房间继续用这个浏览器。
5. 5 分钟内没完成，这个房间照旧记为人机验证，同组熔断规则不变。

程序不会自己去拖滑块或画线。没人操作时，结果和以前完全一样。

## 限制

- 每轮最多 3 次人工验证，同一时间只处理一个；每次最多等 5 分钟。
- 只在北京时间 08:00～24:00 推送，夜里不打扰。
- 链接经 Cloudflare 临时网址（trycloudflare.com）转发，不写进 Actions 日志或证据文件。口令只在这一次验证期间有效。
- 只处理验证类门禁。需要登录的情况（`LOGIN_REQUIRED`）不处理。
- 淘宝是否接受云端浏览器的验证结果，要以真实运行记录为准。运行摘要 `run_summary.json` 的 `human_verification` 记录次数（sessions、solved、timeouts、push_failed）；房间诊断 `passive_observation.human_verification` 记录 `solved` 或 `not_solved`。

## 开关

默认开启。在仓库 Settings → Secrets and variables → Actions → Variables 新建 `HUMAN_VERIFY`，值设为 `0` 即关闭。需要已配置 Bark 的 `WEBHOOK_URL`。

可选环境变量：`HUMAN_VERIFY_WAIT_SECONDS`（默认 300）、`HUMAN_VERIFY_MAX_SESSIONS`（默认 3）。

## 已验证

- 手机实测：练习滑块经云端拖动通过（运行 45083249032，139 次手指操作）。
- 本地端到端：手机模式浏览器里只认触摸事件的滑块，经查看页拖到底通过，云端收到的是触摸事件，没有鼠标事件。
- 离线测试 `tests/v2/test_human_verify.py`：手势顺序、口令过期、超时、夜间不推、推送失败、隧道失败；巡检中验证通过后按真实状态记录，未通过时保持原代码。
