# R1.7｜TCL集团官方旗舰店固定账号 → 自动识别新直播场次

## 用户已确认的需求
用户所说的“绕过”指**上一场直播结束后自动找到下一场新直播**，并不要求破解验证码或绕过淘宝风控。本期只限淘宝／天猫 TCL集团官方旗舰店，账号 2050532947，历史房间号 130742。仍按北京时间整点（每 60 分钟）+ 手动巡检设计，不恢复排班和满播率考核。

## 核心规则
- 固定监控入口：普通公开页面 https://h5.m.taobao.com/taolive/video.html?userId=2050532947 。不把旧直播 URL 当永久入口。
- 固定标识：账号 accountId=2050532947 与账号名称 TCL集团官方旗舰店。必须从自然页面加载时观察到的合法直播详情响应交叉核实账号；历史 roomNum=130742 不再作为新的场次固定门禁。
- 场次标识：在同一验证账号下，必须有新的有效 liveId 和明确 LIVE 状态才能确认新场次。roomNum 变化但 liveId 不变，仍算同一场；房间号变化本身不足以证明开播。
- 同一账号从 liveId A 变为 B 时，关闭 A 的历史片段为 REPLACED_BY_NEW_LIVE_ID（旧直播结束时间未知），新建 B；不可将 B 首见时间伪称 A 的准确下播时间。
- 两次有效 OFFLINE（正常同账号来源且间隔不超过 65 分钟）才能确认常规结束；UNKNOWN / 验证码 / 风控中断证据链，不可当 OFFLINE。
- 60 分钟采样会漏掉整小时之间的短场次；相邻 LIVE 只提供样本跨度估算，不是精确连续直播时长。
- 只做场次切换，不识别真人/数字人，也不能从直播 ID 判断主播属性。

## 新增模块
- probes/lib/r17-session-follow.mjs：提取普通网页的被动直播详情候选状态，固定 accountId、动态 roomNum、基于 liveId 识别新场次的纯状态机。候选默认 sourceAttested=false，未经独立验证的来源不得当作真实 LIVE/OFFLINE。
- probes/r17-single-account-manual.mjs：独立手动入口。**只有显式添加 --manual-public-page** 才以正常 Playwright 浏览器打开用户指定的公开淘宝网页，通过原页面加载过程监听直播详情响应；不直接重放/签名 API，不使用登录 Cookie 或绕过验证码。检测到安全挑战、冲突响应或失败就记录 UNKNOWN，停在本次访问，不循环重试。其余情况下只运行零联网离线模式。
- tests/r17-session-follow.test.mjs：测试账号错配、房间变换、liveId 新旧交替、未知状态、安全降级、相同 ID、下播确认等。
- .github/workflows/r17-session-follow-offline.yml：**仅跑离线完整测试**，不访问淘宝，无 cron。

## 安全手动执行（必须在允许访问的平台环境中）
先安装运行依赖（例如现有受控 Playwright 环境），显式执行：
- node probes/r17-single-account-manual.mjs --manual-public-page --out-dir r17-first
- 后续同账号接力：node probes/r17-single-account-manual.mjs --manual-public-page --ledger r17-first/state.json --out-dir r17-second

如果检测到登录、人机验证、异常流量风控或无有效详情，则立即停止、保留 UNKNOWN；用户本人完成必要验证后，才在正常获准会话中再试。运行不会自动恢复之前的网页登录状态。

## 复验门槛
1. 首次在可正常访问的授权/公开页面取得与 accountId 匹配的 LIVE + liveId，并保存原始验证时刻及页面/响应来源诊断（仅安全字段）。
2. 后续取得同账号不同 liveId 的实际证据，确认真实新场次被独立记录；出现验证码即停止。
3. 将单次 JSON 历史接入可恢复的持久化存储，处理重试去重和多实例冲突，运行至少 24 小时后再考虑启用生产整点巡检。
