# R2.0 京东固定查找路径｜移动端主播主页 → 公开直播身份 → TCL 内部六房间

## 已验证结论（2026-11-10）

本轮普通只读浏览器分别检查了：

1. [TCL官方旗舰店店铺信息页](https://mall.jd.com/shopLevel-721631.html)：主页可见，但导航没有展示本店直播入口。证据：[浏览器核验](https://agent.tinyfish.ai/runs/d1d93650-daa8-4c36-a057-c6c82dbf941e)。
2. [TCL冰箱洗衣机旗舰店首页](https://mall.jd.com/index-619517.html?from=pc)：首页可见，“首页 / 全部分类 / 所有商品 / 超薄平嵌 / 三门 / 十字对开门 / 法式多门 / 对开门 / 滚筒 / 波轮”等导航均无本店直播入口。证据：[浏览器核验](https://agent.tinyfish.ai/runs/53f7a5a3-5f28-4b62-bb8a-be14b6379968)。

**这不证明 OFFLINE，不证明店铺不做直播，也不允许从店铺 URL 数字推导 live room ID。** 旧式 PC 店铺首页不应再作为京东直播查找的唯一入口。

## 移动端操作路径来源

阿里云公开的“直播巡检Agent/如何获取各渠道直播间链接”帮助文档给出的京东取链顺序：

1. 在**手机京东客户端**找到待核验直播间；
2. 点击直播间中的**店铺名**；
3. 进入**主播主页**；
4. 点击右上角三点进入**分享**，选择**复制链接**；
5. 用正常 PC 浏览器打开复制的链接；
6. 使用页面真实展现的**主播主页 URL**作为后续再次核验的固定入口。

参考：[阿里云直播巡检 Agent 操作指南](https://help.aliyun.com/zh/document_detail/3019613.html)（外部流程参考，不代表已经获取任何目标京东主播链接）。

此路径不要求平台开发者账号、商家授权或购买服务，但**尚未完成本项目六房间的真人京东 App 分享取链**；现阶段是已实现可复用接收和核验门禁，不是完成真人移动端识别。

## 固定七步路径

| 步骤 | 动作 | 证据 | 不满足时 |
|---|---|---|---|
| J1 | 从真实京东 App 打开目标店铺的直播间，点击店铺/主播主页 | 能看见店铺、主播名称与账号 | 不采用商品广告或京东采销通用直播间代替 |
| J2 | 主播主页使用三点 → 分享 → 复制链接 | 原始分享链接（仅在用户本地保存） | 取不到则身份保持 UNKNOWN |
| J3 | 将分享文本交给本地只读解析器 | 确认链接属于京东官方域名或第三方短链；剔除敏感参数 | 不访问隐藏接口/重放签名，不在 GitHub 存原始分享令牌 |
| J4 | 正常浏览器打开一次经用户确认的分享链接 | 真实落地地址、主播主页及店铺身份 | 跳到其他账号、登录墙或验证页时停止 |
| J5 | 用可见主页信息独立验证公开京东账号身份 | 店铺名、公开账号标识及当前主页链接 | 未确认不能升级 ops crosswalk 为 VERIFIED |
| J6 | 和内部六房间一一核对 | 真实证据同时连接 ops_room_id、ops_shop_id 和外部账号 | 不能仅依类目（电视/冰洗/空调）猜测房间 |
| J7 | 巡检当次主页/房间，保留 UTC 时间戳、LIVE/UNKNOWN 和证据 | 可判断特定班次的**实际观测状态** | 无真实未开播规则时不输出 OFFLINE 或低于 100% 开播率 |

## 本地分享链接处理

原始分享链接不应提交到公开仓库（可能含带时效的分享令牌或追踪参数）。用户本人或具备合法权限的操作方可以在自己的环境执行：

\`\`\`bash
node probes/r20/jd-mobile-share-cli.mjs < /private/path/jd-share-text.txt
\`\`\`

命令只输出以下安全信息：官方/非官方域名类别、是否第三方短链、路径段数量、是否存在查询参数及待核验状态。它**不会**发起网络请求、不保存原始分享文本、查询参数值、路径内容或 Cookie，也不自动把任何数字写入公开 JD 账号 ID。

- \`JD_DOMAIN_PAGE_TYPE_UNVERIFIED\`：官方京东域名候选，仍需正常页面确认账号身份。
- \`JD_NON_LIVE_PAGE_UNVERIFIED\`：如 \`mall.jd.com\`、\`item.jd.com\`，仅店铺/商品页面，不能单独认定直播。
- \`EXTERNAL_SHORTLINK_UNRESOLVED\`：如历史官方宣传微博中的 \`t.cn\`，必须通过合法普通浏览器再确认落地页面，绝不凭微博文字自动绑定。
- \`NON_JD_DOMAIN\`、\`SECRET_BEARING_URL_REJECTED\`、\`URL_WITH_CREDENTIALS_REJECTED\`：不接受为直播身份数据。
- 即使从 \`m.jd.com\` 或 \`live.jd.com\` 拿到分享链接，默认仍是**候选**，不是被核实的直播账号，也不是当前 LIVE。

## 2026-11-10 新增实证：从历史官方活动链接发现京东直播路由

京东超级品牌日官方 2026-05-23 微博介绍过「5月24日 16:00，TCL 京东自营旗舰店」历史活动，附有短链 \`https://t.cn/AX6U24yU\`。正常浏览器对该公开短链进行**一次**只读核验后，最终实际打开：

\`\`\`text
https://lives.jd.com/#/45583477?origin=3&appid=jdzb&id=45583477&abGroup=control
\`\`\`

随后网页被重定向到 \`plogin.m.jd.com\` 登录页面，页面标题为「京东登录注册」，未获取主播身份、实时直播状态或动态场次证据。没有执行登录或验证码处理。

- 经核实的**URL 路由编号候选**：\`45583477\`。
- 来自官方历史推广的链接，不等于「京东公开主播账号 ID」，也不能与内部 \`ops_room_id\` 按数值合并。
- 访问状态：\`AUTH_REQUIRED\`；直播状态：\`UNKNOWN\`。
- 浏览器证据：[历史活动链接跳转核验](https://agent.tinyfish.ai/runs/46b02dfa-c446-4f63-bc98-e9cb8e494af8)。
- 结构化记录：\`docs/r20/evidence/jd-tcl-official-may2026-live-shortlink-redirect.json\`。

因此，已经确认京东公开直播至少存在 \`lives.jd.com/#/<route>\` 这一种入口结构，但**无法凭 2026 年 5 月历史路由直接推定 2026 年 11 月的实际直播**。

\`probes/r20/jd-mobile-share-intake.mjs\` 现可对该结构提取 \`jd_live_url_route_id_candidate\`，严格保留 \`VERIFIED=false\` 和 \`UNKNOWN\`；并拒绝片段里 \`id\` 与路由号冲突或含签名、登录令牌的链接。**这只是 URL 结构解析测试，不代表已登录或能自动访问平台。**
