# TCL 直播监控 R2.5｜京东场次边界证据引擎（离线实验）

日期：2026-11-10（北京时间）  
基础：R2.4 真人／数字人分段草稿分支。**不修改 main，不部署 Pages，不启动生产巡检。**

## 解决什么问题

R2.3 能读取到内部运营 LIVE 信号并跨运行保存，但没有可独立核验的京东 OFFLINE 负例。这意味着：
- LIVE 第一次被发现 ≠ 平台实际开播时刻。
- LIVE 后网络超时、内部采集进程失联、目录缺失 ≠ 平台已经下播。
- 仅凭一个未证明可靠的 OFFLINE 画面 ≠ 完整停播事件。
- 真人/数字人出镜类型必须独立于店铺 LIVE 状态，不可混为一项考核指标。

## 新增模块

`probes/r25/jd-session-evidence.mjs`：纯 JS、只读输入的场次边界账本；不发任何网络请求。

核心状态：
1. 首次经过核实的 LIVE → 记录第一观察时刻，并建立仅能表示“此时或之前已开始”的区间；实际开播时间为 `null`。
2. 第一次经过核实的 JD 平台 OFFLINE → **待确认**，当前状态显示 UNKNOWN。
3. 5～30 分钟内独立获取第二次合格 OFFLINE → 才能记录“下播已观察确认”；推断边界只在最后 LIVE 与第一次 OFFLINE **之间**；实际下播时刻仍为 `null`。
4. 期间有 LIVE → 清除待定下播，保留同一场次；没有制造一次中断。
5. UNKNOWN、403、超时、截图重复、没有身份确认、非 JD 平台负例、证据超过 3 分钟 → 不可触发下播。
6. 确认 OFFLINE 后再次 LIVE → 新建下一场；其开始区间被上次确认的 OFFLINE 与首次 LIVE 限定。
7. 完播率、准确时长、中断次数、实际开播/下播时刻均保持 `null` 或 `false`；不从离散抽样推断每一分钟连续在播。

## 证据风险与现实限制

当前证据对象里 `source_attested:true`、`identity_verified:true` 仅是**调用方声明**。这个离线模块不会核实视频、网页、店铺 ID 或签名。因此它**不具备生产可信数据源资格**。只有后续接入实际可审计、获准访问的 JD 公开页面负例，证据经过平台身份、截图/会话时间、独立采集核验，才允许在正式部署中使用负例确认。

目前京东来源 `TCL_OPS_READ_ONLY` 只能给出内部 LIVE/UNKNOWN，不能充当 JD 平台独立 OFFLINE 证据，**不得将它的采集异常转换成负例**。

目前不做真人/数字人的自动视觉识别，也不把“数字人只在真人下播后开启”的 TCL 业务规律误当做任何真实直播的证据。
