## 已有能力及边界缺口

现有执行器选择前要求目标明确批准、每次最多两个唯一目标；限制 HTTP 请求方法为 GET/HEAD，阻止 service worker 与下载，校验主页及直播间导航地址，遇挑战或页面访问受阻时停止并保守返回 UNKNOWN。它并不因此自动满足全部观察边界：

- 现有域名校验作用于导航请求；非导航的 GET/HEAD 请求没有同等的域名限制。
- 未建立覆盖所有请求的用途和资源类型限制，无法证明浏览器不会请求媒体流、评论、观众资料或其他超出观察范围的数据。
- 不应假设普通 HTTP 路由已涵盖 WebSocket、重定向或其他网络通道；需要针对可用浏览器版本验证并封禁不允许的通道。
- R3.8 输出包含逐目标标识和观察到的房间标识。交付要求公共日志及普通 Artifact 只保留汇总、时间、错误码和哈希；实际运行前需要收紧输出并验证脱敏。

## 实际观察前的最低验收

1. 按批准配置选择最多两个目标，校验目标身份和允许的 URL；未知或冲突配置直接拒绝。
2. 对整个浏览器上下文采用默认拒绝的网络策略，只允许完成授权页面观察所必需、经核准的 HTTPS 公开域名和请求路径，且仅允许 GET/HEAD。确认导航、子资源、弹窗及重定向都受保护；不得开放未批准账号。
3. 禁止音视频及其流式传输，不请求评论、私信或观众个人资料。对 WebSocket 和其他可能绕过普通路由的通道单独封禁，使用离线或本地受控测试验证；无法证明限制生效则不运行真实目标。
4. 遇 401、403、429、登录墙、验证码或其他挑战，立即停止，记录脱敏原因和时间，结果标记 UNKNOWN，不轮换代理、账号或指纹。
5. 仅发布最小化汇总证据，不记录账号、房间标识、原始页面、Cookie 或其他私有内容；无法确认脱敏时停止发布。
