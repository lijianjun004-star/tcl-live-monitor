## 两个平台与标识

- main 的 JD 过滤器接受经 trim 和小写转换的 `jd`、`jingdong`、`京东`；daily 查询固定传 `jd`，并非从每条记录保留原始平台字段。本轮尚未验证这些别名等价或查询策略对实时来源成立。
- R3.14 的抖音过滤器接受经 trim 和小写转换的 `dy`、`douyin`、`抖音`，将这个**规范化后的值**传给 daily；代码注释称使用来源值，但大小写和首尾空白已变化，因此不能笼统称逐字保留原值。
- 两者区分内部房间与内部店铺编号；抖音来源房店关联不构成公开账号或公开直播间身份关联。R3.14 适配器的 `publicAccountMatched` 默认为 false；内部状态不得视为已验证公开平台状态。
- JD 心跳解析器接受没有 platform 字段的记录；抖音心跳解析器则要求显式平台。无平台的数值编号不能独立证明跨平台身份匹配，JD 路径在 R3.15 接入前须补充证据隔离审查。

## 分页与数据完整性

JD 房间目录检查部分 total、has-more、cursor 和 offset 线索；发现续页或总数不一致时拒绝该目录。没有 total 时标记 `API_RESPONSE_NOT_PROVEN_EXHAUSTIVE`。JD 店铺目录用单独检查判定完整性，检查字段范围与房间并不完全相同；两者均不是通用分页遍历器。抖音房间目录仅在声明 total 等于本页条数、已检查的续页信号均不存在且无完整性警告时才标记完整；没有 total 时为不完整。抖音 `inspectDouyinShops` 未单独证明店铺目录分页完整。各种可能的嵌套分页形态都不能假设已覆盖，也不能用成功的首页请求证明全量。

R3.11 对账代码保留历史房间并将当前未见的记录置为 UNKNOWN；其历史 10 房阈值仅为警告，不能恢复不存在的 ID 或证明全集。历史交付包报告抖音来源曾观察到 10 房、10 店和 10/10 内部关联、1 个 bound；这是历史陈述，不是本轮采集结果。

## 状态与时间限制

JD `evaluateRoom` 和 R3.14 `evaluateDouyinRoom` 仅用当天数据，要求已绑定、心跳来源可用且 LIVE 必须伴随可信采集心跳；采集指标或身份不足时保持 UNKNOWN。这是内部来源信号，不代表公开平台身份已核对。两条现有路径都以 `offlineRuleValidated:false` 调用底层分类器；未校准的下播候选不能当成 OFFLINE。历史状态、缺失日数据、请求失败、心跳不可用或未绑定均不能变成 OFFLINE。`minute_count` 差值是采集计数差，不是经验证的精确直播时长；小时采样无法准确给出分钟级上下播时间。

底层 `classifyTclOps` 的阈值为数据 3 分钟、心跳 2 分钟，并允许一定时钟偏差；这些是已有代码规则，不是经本轮业务校准的准确性保证。R3.15 独立状态门禁仅是纯函数，不能代替来源、身份和规则校准的真实证据。

## 安全缺口与未完成项

1. `networkReader` 有路径 allowlist、GET、超时、拒绝重定向及 1 MB 响应上限，但只请求 JSON 并解析 JSON，未显式校验响应 Content-Type；结构检查主要由各个解析函数承担，不是完整统一 schema 验证。
2. 非成功 HTTP 状态被合并为 `HTTP_ERROR`，扫描器对若干请求使用 `Promise.allSettled` 或逐房捕获错误后继续；它没有完整落实遇 401/403/429/挑战立即停止该目标、保留专门脱敏原因码的 R3.15 要求。必须先修复并测试，不能仅因已有代码为 GET 就认定满足本次停止条件。
3. 已有抓取地址为 HTTP。当前探测未发送身份凭据；未来任何认证数据、Cookie、Token 都不得经明文 HTTP 发送。网络请求是否携带私有标识也应单独审查，且不应写入公开日志。
4. 有些已有内部报告、warning 或状态快照包含房间/店铺编号；它们不是公开安全产物。必须使用经过审计的聚合摘要，不能直接上传普通公开 Artifact、PR 或日志。R3.11 的公开 receipt 专门压制逐房记录，但调用路径和最终输出仍须逐项审查。
5. 本轮未完成含参数的 JD/抖音真实单次采集、schema 验证、逐平台来源/状态准确性或小时级持久化验收；不得将本文件或 HTTP 200 当作这些验收的替代。
