# R3.15 小时级试运行设计（未实现）

## 实际状态

**NOT IMPLEMENTED / NOT OBSERVED。** 此文件是设计和差距清单；当前没有经验证的 R3.15 定时执行、互斥锁、持久化或 24–48 小时运行证据。新建的离线纯函数和模拟测试不能证明跨运行状态恢复。启动真实自动试运行仍需用户明确批准将最小启动器合并到默认分支，或另行批准独立试运行仓库；本轮不做这些操作。

GitHub Actions `schedule` 从默认分支上的工作流触发；实验分支中出现 cron 配置、手动运行或 push 运行，都不能证明 schedule 已启动。GitHub 调度机会也不能当作准时执行的保证；缺失调度槽不得用手动触发补成自动运行成功。

## 仓库已有实现与适用边界

在本轮审计的 main `68382b23f9acf8160c8d86ec154c0ef2ce35af32`，`.github/workflows/jd-r23-scheduled.yml` 使用 `r23-jd-stateful-monitor` concurrency group，恢复同仓库、main、未过期的 JD 状态 Artifact。`.github/workflows/jd-r33-backup.yml` 先在锁外做 freshness 预检查，再调用前述可复用工作流；后者进入共享组后恢复并再次检查主状态，再决定是否采集。此模式值得借鉴，但它属于既有 JD 工作流，不能因此声称 R3.15 京东和抖音已实现跨工作流互斥或原子提交。已有 cron 不得在本轮修改。

既有主流程有来源、接受、状态和上传步骤及后续 gate；不能只凭本地写出的状态文件或日志称上传已成功。历史交付包提到既有 JD 恢复和调度运行，但那些历史记录不是本轮 R3.15 真实运行，也不证明小时级 SLA。

## 设计要求：互斥与恢复

- 每个平台使用独立、固定的共享互斥域；主机会和备用机会必须进入同一个实际生效的临界区，跨工作流单独命名的组不能视作互斥。一个可行方向是主、备共用同一个可复用工作流和相同 concurrency group，并证明调用路径确实共享该组；不要假设配置相似就有锁。
- 备用工作流可锁外预检查，但必须在获得共享互斥后重新下载并验证最新成功状态，再判断 55 分钟 freshness；未能恢复或判定状态时应停止并记录 UNKNOWN，而不是盲目运行或假设成功。是否可作为首次基线须事先有明确、可审计的启动策略。
- 恢复过程需限定同仓库、预期工作流、目标默认分支、有效 retention、schema 和来源平台，并验证状态与运行标识匹配；拒绝跨分支或过期、损坏、未来时间、顺序倒退或不可验证的数据。完整目录未证明时，不可标记目录完整。
- 测试需覆盖锁外预检查与进入锁之间主任务完成、同平台竞争、过期 Artifact、前次失败/取消、上传失败、时钟偏差与恢复错误。仅有模拟测试不能证明云端跨工作流行为，需要真实受控运行证据。

## 成功标记与原子性

“成功采样”必须同时满足：来源读取成功、schema/身份及状态生成检查通过、脱敏状态生成、Artifact 上传成功，且对应运行最终成功。先在内存或临时文件产生**候选**状态，其内记录的观察时间不能单独作为成功凭证；下一次恢复时需核验候选 Artifact 所属运行已成功结束、上传成功并与状态中的 run/attempt 对应，再将其视为已提交成功。缺任一证据即不能刷新成功时间。

Artifact 上传与后续工作流成功之间不是单一原子事务：上传后进程崩溃、作业取消、索引延迟或在成功前上传了候选文件，都可能留下不能作为成功凭证的 Artifact。只选最新创建的 Artifact 而不核验其所属运行最终结果，有误把失败候选当成功的风险；只在上传前写入 `last_success` 也不能证明持久化完成。

共享互斥和完成状态核验可降低重复风险，但不能凭此保证在“来源请求成功、持久化完成前进程崩溃”等情况下恰好一次物理采集。若业务要求严格零重复，必须另行设计可恢复的持久化租约/幂等协议、确认读取可见性和失败语义，并在真实环境验证；不具备这些条件时主备去重验收标为 **NOT IMPLEMENTED**，不得宣称零重复。任何需要增加外部持久化服务或更改生产设置的实现，须先完成具体方案并取得相应授权。

## 抖音 RPA 频率和身份

仅对现有配置中 `scopeApproved=true` 的目标，按确定的批准名单分六批，每次最多两个唯一账号；实际执行时应持久化每账号上次尝试时间并在共享限频域中复核，确保任意滚动 60 分钟内同一账号至多一次常规观察。延迟启动或重试不能绕过这一限制；无法可靠恢复限频记录时停止对应观察。遇验证码、登录墙、401/403/429 或挑战立即停止当前目标并记 UNKNOWN，不切换代理、指纹或账号来绕过。无直播入口、HTTP 200、名称相似均不构成 OFFLINE/LIVE 或身份验证。

目前没有实现可验证的持久化限频器、批次调度器或本轮真实浏览器结果；本设计不宣称十二个账号已完成观察或桥接。
