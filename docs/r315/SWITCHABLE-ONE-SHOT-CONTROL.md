# R3.15 自动/手动开关式单次巡检控制

状态：**已实现控制平面草稿；尚未合并默认分支；尚未连接真实来源采集器。**

## 用户可操作的四种动作

通过 GitHub Actions 的 `R3.15 Switchable hourly one-shot monitor` 工作流（这是第一版操作入口，不是手机网页控制面板）：

| 动作 | 作用 | 是否立即采集 | 是否修改自动开关 |
|---|---|---:|---:|
| `status` | 查看京东/抖音自动开关和来源就绪状态 | 否 | 否 |
| `run_once` | 立即执行一次指定平台或两平台任务 | 只在来源授权和采集器就绪后 | 否 |
| `enable_auto` | 打开指定平台的自动小时模式 | 否；从下一个小时槽生效 | 是 |
| `disable_auto` | 关闭指定平台的自动小时模式 | 否；后续计划槽不再读取来源 | 是 |

手动单次与自动模式互相独立：自动开关关闭时仍可手动执行一次；手动执行不会改变自动开关。

## 自动时间

- 唯一 schedule：UTC 每小时第 35 分钟，即北京时间每小时第 35 分钟。
- 只在北京时间 06:30 至次日 02:00 的运营窗口内执行。
- 因而每日首个计划槽为 06:35，末个计划槽为 01:35。
- GitHub schedule 是尽力触发，不能承诺准点 SLA；每次以真实 Actions 运行时间为准。
- 不设置常驻进程、浏览器轮询、直播连接或视频拉流。
- 自动开关 OFF 时，GitHub 仍会每小时启动一个极轻量的开关检查任务；它只读取独立控制文件并退出，不请求京东/抖音业务数据源，也不产生直播状态结果。若要求 OFF 时连 GitHub 检查任务都不启动，需要可动态暂停的外部调度器，GitHub 固定 cron 本身无法做到。
- 单个 workflow job 最大 5 分钟；完成一次决策/采集后退出。

## 持久化开关

- 控制状态文件：`config/r315-runtime-switch.json`。
- 状态分支：`r315-runtime-control`，与 `main` 和正式业务数据分离。
- 京东、抖音分别有独立 `autoEnabled` 位。
- 初始状态两平台均 OFF。
- 控制工作流以 `contents:write` 更新该状态分支；状态更新本身不触发采集。
- 自动 schedule 和手动 run-once 使用同一组并发门禁，防止同时运行。

## 当前安全阻断

初始状态：
- `sourceAccessApproved.jd=false`
- `sourceAccessApproved.douyin=false`
- `adapterReady.jd=false`
- `adapterReady.douyin=false`

因此目前：
- `run_once` 会明确显示 `SOURCE_ACCESS_NOT_APPROVED`，不访问任何业务来源；
- 即使手动把自动开关打开，schedule 也只输出阻断状态，不访问来源；
- 自动/手动开关控制平面可测试，但**不能称为真实直播巡检已经接通**；
- 当前 CLI 编译门禁固定 `runnerReady=false`，没有可从配置文件打开的旁路；
- 只有完成可信来源授权、审核各路由 Schema、接入采集器并通过独立验收后，才可在代码中启用 runner。

1. 审核控制分支读写和权限；

4. 接入实际采集器；

6. 连续观察 24–48 小时，统计计划槽、实际成功槽、间隔和失败原因。
