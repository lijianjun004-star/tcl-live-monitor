# TCL 多平台直播监控系统｜模型通用项目上下文（唯一权威入口）

更新日期：2026-11-04。适用于 Claude / ChatGPT / Codex / Gemini。其他 `CLAUDE.md`、`AGENTS.md` 只指向本文件，避免版本分叉。

## 1. 项目范围、刚性原则

- **本项目仅处理 TCL 京东、淘宝/天猫、抖音直播间状态自动监控与满播率考核。** 不属于 TCL 智能练播房、不属于 TCL 新主播12周养成计划；不可混库、混仓库、混部署。
- 用户目标：全云端无人值守、手机和电脑关闭也继续监控；网页可在手机和电脑使用；**零新增费用且希望长期免费**。技术研究必须如实声明免费配额和第三方平台可用性**不能永久保证**。
- **不购买服务器、不依赖个人电脑24小时开机、不注册第三方直播平台开发者应用、不要求主播/商家授权或提供账号密码、Cookie、签名密钥或 Token；不绕过登录、验证码及反爬控制。**
- 只尝试公开游客可访问的页面/合理授权的访问路径。公开页面不可判定时一律 `UNKNOWN`，不硬判 `OFFLINE`。
- 先测试与审计，后部署；未经用户确认与权限验证不得开启生产监控、收费资源或云端写入。
- 用户希望通过 ChatGPT 统筹审核、Codex 负责开发和自动测试、Gemini/Claude 按需独立复验；角色分工不是工具已经实际接通的证明。

## 2. 核心业务规则（用户已确认）

| 需求 | 规则 |
|---|---|
| 平台 | 京东、淘宝/天猫、抖音，其他不做 |
| 监控粒度 | 按实体直播间/账号/场次；多账号、多平台同播需要绑定关系，避免时长重复计算 |
| 排班巡检 | 排班时间内每约5分钟；排班外每约15分钟（仅为计划频率，云端能力和稳定性尚未验证） |
| 迟到 | 超过计划开始时间5分钟，且证据充分才判迟到；采样不精确时需标注估计和置信度 |
| 中断 | 连续至少10分钟有可靠停播证据才记录中断；网络异常和缺样不视为停播 |
| 排班外开播 | 可以记录，不计入该排班考核 |
| 排班 | 固定排班 + 动态增播/调班/取消；允许用户原 Excel 格式导入/标准模板导入；预览确认，仅调整尚未开始的排班，开始后冻结依据 |
| KPI | 开播率、计划总直播时长完成率、按实体直播间平均完成率、每房间独立成绩；必须同时显示监测覆盖率及数据置信度 |
| 考核口径 | `LIVE`、有证据的 `OFFLINE`、`UNKNOWN` 三态；有缺样时标记暂定，不进行正式扣分，不得把抽样估算称为精确结算时长 |
| 数据存储 | 巡检明细90天；日/月/年统计与长期趋势保留；不能借免费方案承诺无限容量 |
| 权限 | 管理员 + 员工只读；内置网页通知中心，不依赖外部消息推送 |
| 终端与时区 | 手机/PC响应式，统计和排班统一北京时间 `Asia/Shanghai` |
| 故障恢复 | 失败自动重试/补查，记录缺测原因；无法复核则 `UNKNOWN`，不得补造事实 |

注意：上述是产品目标和业务口径，并不等于已有系统全部实现。

## 6. 零费用与无人值守技术结论

- 理想方案：轻量状态采集（仅公开合法来源）+ Cloudflare Workers 定时器 + D1 存储 + 静态仪表盘 + 显式 `UNKNOWN` 和可审计的复测。
- **但** Cloudflare Worker 免费版不能保证永久免费/所有限制不变，免费浏览器渲染资源与网络环境也无法覆盖大量 Playwright 高频轮询；如果状态采集依赖完整浏览器，不应伪称 Worker 单独可以满足需求。
- GitHub Actions 已被用于研究性单次公网测试，存在定时执行延迟与跳过/政策限制，不作为长期生产监控运行器。
- CloudBase 免费体验与腾讯账号已有环境额度要现实核验，不可把免费试用当永久免费。
- 无开发者应用、无商家授权的条件下，是否存在合法稳定的三平台状态源**尚不确定**；若公开页面不提供可持续证据，必须给出可行性阻断结论，而不能虚构成功。

## 7. 必须优先解决的问题（按顺序）

1. GitHub：修复新仓库实际写入/浏览器可操作环境，或由有权限的用户/Codex 执行导入；不可因为元数据 `push:true` 就宣称已写入。
2. 源码：从两个历史诊断分支只读拉取最新版，和本 ZIP 的 R1–R3 原型做差异审计；拒绝直接复用旧仓库生产 Cron。
3. 京东：在有授权、合法可见的参考页面中确认表格数据来源、真实房间标识、状态字段及时间戳；无访问权就标记阻断。
4. 抖音：取得真实停播样本，验证 `LIVE/OFFLINE/UNKNOWN` 规则及不同场次房间 ID 变化。
5. 天猫：复测既有公开访客渠道的 3/3 成功快照以及全部 `UNKNOWN` 反例，验证不把失败判停播。
6. 免费运行：实测小样本真实云端定时调度 48 小时、预算与额度、缺样率、异常补查；不达标则不得进入正式考核。
7. 产品：排班 Excel 导入、实体直播间映射、五分钟宽限、十分钟中断、三个层级 KPI、手机看板、权限与历史保留；优先校验这些是否已经实现而非重新承诺。
8. 所有变更限定新仓库 `lijianjun004-star/tcl-live-monitor`；遵循独立分支/PR/测试/审查；旧仓库只读。

## 8. 交接底线

- 严格区分**用户确认、历史报告、仓库源码、实际运行复验、合理推测**。未验证的事情写 `未验证`。
- `UNKNOWN != OFFLINE`；HTTP 200 != LIVE；一次 LIVE 快照 != 直播时长；本地单元测试 != 云端 24/7；GitHub 账号 admin != 当前集成 API 可写。
- 对用户已有的素材和需求，不要重复询问；仅当缺少必须由用户提供的真实证据/权限时一次只问一个问题。
- 安全禁止事项：不索要密码、Cookie、AppSecret、Token；不绕过登录验证码、风控、平台授权或访问控制；不往 GitHub 公共仓库存个人考核记录。
- 最终交付需要代码 + 测试命令 + 可核对的真实证据 + 未通过项 + GitHub PR/SHA/运行 URL 或明确阻断说明。
