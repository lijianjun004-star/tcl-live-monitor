## 预检

此预检只比较来源配置。它不会查询 DNS、连接来源、发起工作流或输出地址。

`node scripts/check-jd-source-config.mjs` 从进程环境读取以下值。由操作员在受控环境填入，避免写入命令参数、仓库或公开日志。

| 环境变量 | 含义 |
|---|---|
| `TCL_OPS_BASE_URL` | 对照工作流实际生效的来源配置 |
| `JD_APPROVED_SOURCE_ORIGIN` | 来源维护方确认且对采集环境授权的正式入口 |
| `JD_LEGACY_SOURCE_ORIGIN` | 可选。已知旧回退入口在待复核时填入，比较时不会公布旧地址 |

来源需为明确的 HTTP(S) origin。允许根路径和合法端口。账号密码、查询参数、片段、多余路径、隐式 URL 修复或无效端口都会被拒绝。地址匹配返回 `CONFIG_MATCH` 和退出 0。缺失、无独立批准记录、旧入口待复核、无效或不匹配均返回固定错误码和退出 2。每份结果都保留 `reachability=NOT_TESTED`。正式入口由维护方重新确认后，若确实仍是原地址，使用其已确认配置进行等值核对，并独立核查可达性。

共享京东采集器使用同一形态校验，保留已有合法 HTTP(S) 入口的请求行为。网络或响应失败继续由来源扫描记录为 `CONNECT_TIMEOUT`、`NETWORK_UNREACHABLE`、`HTTP_ACCESS_DENIED` 或其他固定代码。配置无效会在发请求前停止。正常来源配置和已接受的房间证据要分别验证。

## 待批准切换

1. 来源维护方先核对正式入口、服务监听和允许的采集网络。若 GitHub runner 的访问路径属于审批范围，请由维护方检查路由、防火墙、ACL、反向代理或来源日志。建议仅核对现有京东目录 GET 路径的一次只读来源响应。若仍超时，记录测试位置、时间和脱敏错误码，保留现行 `UNKNOWN`。
2. 正式入口确认后，由有权限人员通过原有受控配置更新来源。r23 使用该配置并将其交给 r33 备份，r327 有独立的工作流入口。是否改为在生产缺失来源时显式阻塞，需和既有流程一起批准。此候选只交付预检与共享代码，生产工作流、cron、权限、Secret 和固定 SHA 保持现状。
3. r23 仍有两处旧 SHA checkout。生产激活需要单独选定经批准的不可变 SHA，同时验证 r23 无历史的首次初始化、r33 共享调用、旧新 Artifact 的同代校验及中断锁留存。先用保全的真实历史做兼容检查，然后按批准范围分别验收 r23/r33 的一次只读采集和 r327 的失败状态保存与恢复。
4. 回退需要保全变更前后 state、summary、锁、中断标记及运行标识。确认旧实现可读的同一次状态与摘要，再将代码、pin 或配置逐项回到已批准版本。旧地址若仍不可用，保留失败与 `UNKNOWN`，避免把旧成功时间当作新的来源证据。
