# TCL 直播监控 R1.6｜北京时间整点巡检＋手动巡检

## 本阶段范围
- 不需要排班表，不计算满播率，不识别主播姓名和换班。
- 三平台目标是淘宝／天猫、京东、抖音。本轮只做第一家：TCL集团官方旗舰店（账号 2050532947；历史房间 130742）。
- 北京时间每个整点巡检一次（00:00 到 23:00）；支持用户手动触发。
- 分别存储计划整点和实际采样时刻，LIVE/OFFLINE/UNKNOWN 三态；首次发现上下播和估算时间跨度，均不冒充真实平台事件时间。
- 无需登录或突破平台限制，不新增付费；有可访问的回放时单独补核真人直播时长。

## 已实现的代码
1. probes/lib/r16-hourly.mjs：小时边界、计划/实际时间分离、手动/定时去重、小时级历史场次整理，兼容 R1.4 JSON 账本。
2. probes/r16-hourly-run.mjs：纯离线试运行，只记录 UNKNOWN 尝试，不提供伪造 LIVE/OFFLINE 命令；输出手机 HTML、CSV、JSON。
3. tests/r16-hourly.test.mjs：小时边界、重试幂等、手动多次运行、失败降级、两次 OFFLINE 确认结束、历史 LIVE 过期。
4. .github/workflows/r16-hourly-first-store-offline.yml：CI 与安全日志 workflow_dispatch；没有 cron，没有淘宝网络请求。

## 如何测试
- node --test tests/*.test.mjs
- node probes/r16-hourly-run.mjs --trigger manual --out-dir r16-preview
- node probes/r16-hourly-run.mjs --trigger scheduled --now 2026-11-08T05:00:00Z --out-dir r16-hourly-demo
- node probes/r16-hourly-run.mjs --trigger manual --ledger r16-preview/state.json --out-dir r16-preview-2

HTML 在 r16-preview/index.html，状态账本在 state.json，表格在 attempts.csv。

## 验收门槛
- 旧 Actions 有 LIVE 历史证据，也发生过 RGV587 限流；真实淘宝状态源没有稳定验收。
- 当前手动模式只表示手动记录一次无法读取的尝试，不是已经读取直播状态的真实巡检。
- 历史快照不代表当前 LIVE，UNKNOWN 不等于 OFFLINE；60分钟间隔不能精确确认直播总时长。
- Actions 的 schedule 只在默认分支触发，整点可能延迟、漏触发；目前尚未配置真正 schedule。
- 当前没有跨不同 Actions workflow run 自动恢复状态；state.json 仅为可携带的恢复数据，长期持久化待验收。
- 必须先验证正常允许的数据源、多轮真实状态、跨次数据保存、至少 24h 连续巡检，再决定合并和启用整点自动任务。
- 所有变动只在独立分支；不合并 main，不改练播房，不启用正式考核。
- 本分支依赖 R1.5 及更早的未合并草稿版本。
