## 新增能力

- `probes/lib/ops-room-registry.mjs`：合法授权后已导出的三平台内部房间、店铺 JSON 适配；严格在 `(platform,opsRoomId)` 与 `(platform,opsInternalShopId)` 同平台内关联；不推断官方商城店铺 ID / 动态 liveId / Douyin secUid。
- `probes/lib/merge-live-observations.mjs`：读历史京东报告与公开监控 `probe-report.json`，仅允许新鲜、有来源、无冲突的 LIVE；历史过期、候选 OFFLINE、重复房间、页不完整均不允许生成正式考核结论。
- `probes/lib/coverage-audit.mjs`：输出证据数量、店铺归属、未映射身份、尚未完成的验收条件。
- `probes/render-offline-preview.mjs` 与 `preview/template.html`：纯本地对账页；可查看三平台账户身份与来源店铺，导入只读投影、导出 CSV。不是运营后台 CRUD 或正式监控站。
- 所有私人数据写盘使用 `0600` 及独占写；`.gitignore` 增加 `*.private.json` 等保护，不能把源站 JSON 直接提交公共仓。
- 对外展示的运营房间名统一替换为“运营巡检房间 + ID”，不复制主播或采集端姓名；原始令牌、心跳 Session Key、GMV、Cookies 不进入输出。

## 运行

```bash
node --test tests/*.test.mjs
node probes/import-ops-room-registry.mjs \
  --jd-report fixtures/jd-all-safe-report-20261105.json \
  --targets config/probe-targets.json \
  --unmapped fixtures/ops-douyin-history-unmapped.json \
  --out room-registry.private.json
node probes/build-three-platform-view.mjs \
  --registry room-registry.private.json \
  --jd-report fixtures/jd-all-safe-report-20261105.json \
  --out three-platform-view.private.json
node probes/audit-three-platform-coverage.mjs \
  --registry room-registry.private.json \
  --jd-report fixtures/jd-all-safe-report-20261105.json \
  --out coverage-audit.private.json
node probes/render-offline-preview.mjs \
  --view three-platform-view.private.json \
  --out three-platform-preview.private.html
```

### 真实源站导入（仅已获授权的本地环境）

```bash
node probes/import-ops-room-registry.mjs \
  --rooms private-rooms.json --shops private-shops.json \
  --targets config/probe-targets.json \
  --out room-registry.private.json
```

源站输入仅限已授权只读 GET 下载的 `/api/capture/rooms` 与 `/api/shops` 完整 JSON。没有 total、分页仍未齐或存在重复冲突，均拒绝标注“已覆盖全量”。**不要把源站含主播姓名、个人信息或成交额的响应原文提交至公共仓库**。
