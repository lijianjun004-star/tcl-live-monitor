# CloudBase 云托管：淘宝直播风控对照测试

用来回答一个问题：**从腾讯云上海地域的服务器打开淘宝直播间，会不会像境外服务器那样被拒？**

每次测试用真实 Google Chrome（有头模式，跑在虚拟显示器上）以游客身份打开一个直播间，不登录、不点击，记录：

| 记录项 | 含义 |
|---|---|
| 数据接口返回 | `mtop.roomstudio.live.detail.get` 是「SUCCESS」还是「FAIL_SYS_ILLEGAL_ACCESS::非法请求」等风控拒绝 |
| 页面 / 视频流 HTTP 状态 | 是否出现 400、403 |
| 视频 | 播放时间是否在走、画面尺寸 |
| 截图 | 每次一张，只存在容器临时目录，需令牌查看 |

| 结果 | 判定 |
|---|---|
| 播放中 | 数据成功，视频时间在走 |
| 数据成功 | 数据未被拒，但视频没走（未开播、拉流慢等） |
| 被拒 | 数据接口被风控拒绝，或页面/视频流 HTTP 400/403 |
| 未定 | 预算内没拿到数据接口结果 |

## 境外基准（2026-11-23，Claude 云容器，非大陆机房 IP，游客）

- 同一份代码 1 次：**被拒**（令牌为空 → 非法请求，播放器「加载失败」）。
- 此前手工 6 次：3 次数据成功、3 次加载失败（其中 1 次已确认是「非法请求」）；没有出现 HTTP 400。

## 部署（控制台菜单名称可能与下文略有不同）

1. 在**上海地域**的 CloudBase 环境打开「云托管」，新建服务（例如 `taobao-probe`）。
2. 部署方式选上传代码包，上传本目录打成的 ZIP（`Dockerfile` 在压缩包根目录）。
3. 服务端口填 **8080**；规格选 **1 核 2 GB** 或更高（Chrome 至少需要 2 GB 内存）；实例数最小 0、最大 1。
4. 环境变量添加 `PROBE_TOKEN`，值为你自己生成的 16 位以上随机字符串。不要复用看板写入令牌。
5. 开启公网访问，记下 HTTPS 访问地址；健康检查路径可填 `/healthz`。

构建失败时：

| 现象 | 处理 |
|---|---|
| 拉取 `python:3.11-slim-bookworm` 失败 | 构建参数 `BASE_IMAGE` 改为 `mirror.ccs.tencentyun.com/library/python:3.11-slim-bookworm`，或直接改 Dockerfile 第一行的默认值 |
| 下载 `dl.google.com` 的 Chrome 失败 | 在能访问的电脑下载 `google-chrome-stable_current_amd64.deb`，放进 `vendor/` 再打包 |

## 测试

1. 手机打开服务的 HTTPS 地址，输入 `PROBE_TOKEN`。
2. liveId 默认是 12:41 实测的六店场次。场次可能已下播，下播不影响风控结论，但看不到视频；想看画面，就在麦兔上打开 TCL 搜索页复制当前的 liveId 替换。
3. 点「开始测试」。默认每个直播间间隔 30 秒，服务端至少间隔 20 秒，同一时间只跑一个。
4. 一轮 6 个约 5 分钟。可以隔一段时间再跑一轮，看结果是否稳定。

## 结果怎么读

- 上海大多是「播放中 / 数据成功」：境外 IP 假设成立，可以继续在云托管上做六店采集（下一步要解决扫码登录和登录状态保存）。
- 上海也经常「被拒」：淘宝的风控针对机房 IP，不分境内境外；采集应放在麦兔这类云电脑上。

## 费用与清理

最小实例为 0 时，没有请求就不占实例（以 CloudBase 实际计费规则为准）。测完可以停止或删除服务；截图在实例回收时一并消失。

本服务不登录淘宝、不采集六店、不写看板数据。
