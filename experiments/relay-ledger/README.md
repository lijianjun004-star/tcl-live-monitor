# 离线派发账本模型（不能启用）

此纯状态转换模型补齐 #105 未实现的**模拟**跨轮故障与关联审查，不被 Worker 导入，不访问任何网络，不持久化，不产生派发。所有返回值 dispatch=false；accepted 仅表示模拟状态转换被接受。

可序列化 READY → PENDING → SOURCE_BACKOFF / REVIEW_REQUIRED；预留先于 POST，HTTP接受保持 PENDING。超时或未知结果保持待审；回写丢失仍可从先前预留恢复为阻塞。缺失/损坏/反序时间/重放机会均拒绝。来源失败须显式传入 reviewDelayMs，未猜测生产退避时间；到期仍不自动解除。解除需要绑定整个状态摘要与审查引用。

审计事件带 attemptId、非敏感 runId/evidenceRef/reviewRef 和状态摘要链。不记录 token、原始错误或响应正文。摘要只能检测意外损坏，**不是防篡改签名或可信远端来源证明**。feedbackReviewed/reviewRef 是调用者声明，不验证人或事实。

下一阶段仍阻塞：需已批准的原子持久存储、CAS/串行互斥、真实派发关联协议、反馈认证、恢复批准验证及预算。双进程各拿到 READY 副本仍可能各自预留，纯模型不能提供分布式 exactly-once；不得接入任何发送路径。记录达到1000条即阻塞，不静默截断审计，归档策略需另审。

合成测试包含序列化后多轮、丢失回写、未知结果、错误反馈、失败退避、过早/错误摘要解除、重放与状态/审计损坏。运行 `node scripts/test-offline-all.mjs`；无需服务、账号、扩展或依赖安装。
